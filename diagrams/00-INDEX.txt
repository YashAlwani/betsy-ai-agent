====================================================================
 BETSY — DIAGRAM INDEX (what each picture shows)
====================================================================

This folder holds the diagrams used by Betsy's design documents.
Each one is a Mermaid file (.mmd) — a small text file that describes a
picture. To see the actual picture, open the .mmd file in any Mermaid
viewer: paste it into https://mermaid.live, view it on GitHub, or open it
in a code editor with a Mermaid preview.

Every entry below says, in plain words, what the diagram shows, which
document it belongs to, and where the matching code lives.

--------------------------------------------------------------------
 PIPELINE  (Betsy's simple, one-step-after-another agent)
--------------------------------------------------------------------

pipeline-overview.mmd
  The six steps of one pipeline run, shown left to right:
  ingest -> detect -> evaluate -> decide -> act -> audit. Also shows that
  anything needing a person is parked in the approvals queue.
  Document: docs/pipeline-architecture.txt
  Code:     pipeline/graph.py

pipeline-dataflow.mmd
  The same six steps stacked top to bottom, with a one-line note on what
  each step actually does to the data.
  Document: docs/pipeline-architecture.txt
  Code:     pipeline/nodes/ (ingest, detect, evaluate, decide, act, audit)

pipeline-approval.mmd
  How the human checkpoint works: the agent drops a ready-to-go purchase
  order into the approvals queue, the run finishes, and Jenny approves or
  rejects it later from her screen.
  Document: docs/pipeline-architecture.txt
  Code:     pipeline/nodes/act.py, server/routers/approvals.py

--------------------------------------------------------------------
 ORCHESTRA  (Betsy's advanced agent — several specialists at once)
--------------------------------------------------------------------

orchestra-overview.mmd
  The five steps of an orchestra run, with the three specialists
  (Inventory Monitor, Supplier Scout, Invoice Auditor) running together.
  Document: docs/orchestra-architecture.txt · Code: orchestra/graph.py

orchestra-conflict.mmd
  How Betsy settles it when two findings clash on the same item — the
  fixed precedence rules that decide which concern wins.
  Document: docs/orchestra-architecture.txt · Code: orchestra/graph.py
